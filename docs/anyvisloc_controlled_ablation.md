# Контрольний notebook AnyVisLoc

[Відкрити notebook](../notebooks/anyvisloc_controlled_ablation.ipynb).

Мета — розділити вплив адаптера, matcher, підготовки ділянки та шуму prior.
Початковий перелік: Scene_05/L05_0969, Scene_08/L08_0049, Scene_11/L11_0545.
Це ті самі кадри, що в попередній діагностиці видимості. Всі зображення чисті,
без додаткового resize до 1600 px. Aerial і satellite порівнюються окремо.

| Етап | Що перевіряє |
| --- | --- |
| A_author_Roma | Авторський `run_avl_match_loc.process_one_sample`, GT crop/resize, RoMa |
| B_adapter_replay | Production `match_candidate` з тими самими crop і записаними відповідностями A |
| B_adapter_live | Production адаптер із повторним RoMa inference, тим самим seed і входами |
| C_SP_LG | Ті самі фактичні зображення matcher; замінено тільки RoMa на SP/LightGlue |
| C_SP_LG_p | Окремо вимкнено yaw-поворот crop |
| D0_search_exact_pose | Повний CAMP/SP-LG пошук проєкту з точною позою як контролем |
| D1_search_noisy_pose | Той самий пошук із шумом prior, σXY=20 м, профіль main |

A/B/C/D0 — діагностичні режими з використанням еталону при підготовці входів.
Вони не оцінюють GPS-denied навігацію. D1 отримує тільки зашумлений prior; еталон
використовується для симуляції prior та оцінювання після inference.

Авторський runner викликається в тому самому процесі з тим самим тілом функції.
Спостерігачі записують входи й виходи matcher/PnP, не замінюючи їх значень.
У B повернутий crop має явну афінну трансформацію до повної карти; production
`match_candidate` отримує її через необов'язковий `map_transform`. У controls-v2
окремий `map_points_to_local` відтворює авторські етапи float32-округлення перед
індексацією DSM: зворотний resize, inverse rotation, offsets і переведення у метри.
Це усуває чисельну відмінність від згортання всіх етапів в одну матрицю; пороги
перевірки не послаблюються. Звичайний
notebook видимості у режимі `map_alignment='none'` використовує тотожну
трансформацію; поточний `prior_yaw` передає зворотне перетворення повернутої карти.

Gate A/B перевіряє хеші фактичних пікселів, відповідності, входи PnP, кількість
inliers і повну 3D-позицію. Допуски: 0,001 для координат відповідностей/входів;
0,01 м для позиції. Два невдалі PnP не підтверджують паритет пози: до C/D потрібна
хоча б одна перевірена пози та успіх усіх інших порівнянь. Незбіг зупиняє notebook.

Нейромережеве виконання потребує Google Colab GPU. Скопіюйте всю папку
`scripts/visibility_localization` у Drive, відкрийте новий notebook, перевірте
CODE_ROOT і архіви, перезапустіть Python-сеанс та виконуйте комірки зверху вниз.
Додаткові RoMa/DINOv2 checkpoint завантажуються за офіційними посиланнями
з README авторів. CAMP і дані повторно використовуються, якщо вже є на диску.

Результати: `RESULTS_ROOT/anyvisloc-controls-v2`. Артефакти: `manifest.json`,
`model_identity.json`, `adapter_parity.csv`, `all_controls.csv`, `summary.csv`,
`paired_errors.csv`, `records/*/result.json`, `correspondences.npz`, lossless PNG
входів matcher та графіки. Дані, вихідний код і ваги фіксуються хешами.
За замовчуванням результати на тимчасовому диску Colab; для постійного збереження
встановіть SAVE_RESULTS_TO_DRIVE=True перед запуском. Зміна ідентичності вимагає
нового CONTROL_RUN_TAG. Технічні помилки зупиняють виконання без прихованого
виключення кадрів; завершені записи залишаються доступними.

Спільний критерій — валідна PnP-позиція з похибкою XY ≤10 м; знаменник містить усі
завершені спроби, включно з невдалими PnP. Прапорець accepted нашого адаптера
зберігається окремо. Повний запуск містить 42 рядки: 3 кадри × 2 карти × 7 етапів.
Середовища Python 3.13/NumPy 2 відрізняються від старих обмежень авторів:
це контроль коду на однаковому поточному середовищі, не точна репліка таблиць статті.

Локально перевіряються синтаксис/schema notebook, CPU-тести й оригінальна
геометрія matching/PnP на синтетичних відповідностях. Реальний RoMa/SP-LG/CAMP
на цих кадрах перевіряється лише фактичним GPU-запуском; результати не вигадуються.
