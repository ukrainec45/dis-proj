# Протокол correction-delta-v1

Дата реалізації: 2026-11-14. Погоджені ціль, пілот, кандидати й межі Δe.
Основний обсяг і незалежний тест погоджуються після пілота. Усе research_only.

## Подія та інформаційна межа

e — евклідова горизонтальна похибка позиції в метрах відносно одного еталона.
Δe=e_before−e_after. Відмова зберігає prior. Діагностична позиція відкинутого
PnP не застосовується. Технічна помилка не утворює клас відмови й окремо
входить у знаменник загальної кількості запущених спроб.

Класи: reject; accepted Δe у (-∞,-20), [-20,-5), [-5,-1), [-1,1), [1,5),
[5,20), [20,+∞). На межі -1 значення входить у neutral, на +1 — gain_small.
Ця асиметрія лише задає однозначність реалізації. Вона не є фізичною межею.
Пороги евристичні; вихідні неперервні значення зберігаються без обрізання.

Перед прогнозом недоступні camera RGB, GT, реалізована похибка prior,
трансмісія конкретної синтетичної маски, inliers, matches та reprojection.
Модель знає категорію сценарію та його фіксовані параметри, а не майбутню
реалізацію маски. Позиція query є noisy prior/плановим станом.

Камера імітується за метаданими AnyVisLoc з доданим шумом орієнтації/висоти:
main profile σyaw=5°, σtilt=2°, σz=5 м. Це умовна постановка, не запис VIO.
Пілот використовує aerial/DSM; перенесення на satellite чи Sentinel окреме.

## Ознаки та фрагмент карти

Геометрія: головні σ горизонтальної коваріації, σyaw/tilt/z, висота над
локальною DSM-площиною, nadir angle, FOV, GSD, розміри пошуку, покриття та
дві категоріальні ознаки сценарію. Видима область наближена площиною з DSM
у prior-позиції; якщо DSM там недоступна, AnyVisLoc adapter використовує
медіану сцени, що є явним наближенням. Висота над еталонною поверхнею у GT
не передається прогнозу.

Контекст — очікуваний center-crop footprint плюс три головні σ, resampling
до 256×256. Карта не псується синтетичним туманом. Map features: std сірого,
ентропія 32-bin, середній модуль градієнта, частка сильних Shi–Tomasi відгуків
(поріг 1% локального максимуму, floor 1e-8) та максимум автокореляції зі
зсувами 16/32/64 пікселі по двох осях. Межі padding/nodata виключаються.
Це компактні базові характеристики, не відтворення чужого методу та не
доведені фізичні показники ймовірності. Наявність кількості текстурних
елементів не гарантує однозначної локалізації.

## Моделі та калібрування

- Constant: частоти train з Laplace +1 на кожний із восьми класів.
- Logistic: lbfgs, C=1, максимум 2000 ітерацій, без ваг класів; масштабування
  за train, нульові std замінюються на 1. Відсутність збіжності — помилка.
- Forest: 300 дерев, max_depth=6, min_samples_leaf=5, seed=42, один CPU worker,
  без class weights. Geometry та map варіанти використовують однакові параметри.
- Jev: pinned jev-1.14.0, Choice з тими самими класами; числовий та image
  варіанти. Ваги не навчаються. Промпт і фіксовані пороги локалізатора
  збережені. У text input не потрапляють scene_id/GT/результати зіставлення.

Це початкові прозорі конфігурації без hyperparameter search. Не заявляється,
що вони оптимальні. Зміна налаштувань після пілота потребує нової версії
досліду до остаточного тесту. Для відсутніх train-класів регресія/ліс мають
числовий floor 1e-12, що не є емпіричним підтвердженням їхньої ймовірності;
missing_classes явно записуються. За однокласного train кандидат переходить
до явно позначеної константи, а не удавано навчає класифікатор.

Для кожного кандидата одна температура T>0: softmax(log(clip(p,1e-12,1))/T).
T мінімізує log loss тільки на calibration, log(T)∈[-3,3]. Порівнюються raw
і calibrated. Вибір — мінімальний validation log loss; при точній рівності
стабільний порядок constant → logistic_geometry → logistic_map →
forest_geometry → forest_map → надані Jev кандидати, raw перед calibrated.
Дані не об’єднуються для повторного навчання після калібрування.

## Незалежність і оцінювання

Сцена, кадр і audited spatial_group не перетинають splits. Метадані самі не
доводять відсутності перекриття територій: дослідник має записати аудит.
Залежні повтори не перетворюються на незалежні знімки. Уже переглянуті
Scene_05/07/08/11/21 не допускаються до test.

Основна метрика — multiclass log loss (clip 1e-12 лише для обчислення).
Brier — середня сума квадратів по восьми класах, без ділення на 8.
Reliability: п’ять фіксованих інтервалів ймовірності. Події accept,
improve(Δe≥1), worsen(Δe<−1), severe_worsen(Δe<−20). Остання подія
оцінює лише прийняті погіршення; technical errors окремі.

Conditional RPS — середній квадрат різниць CDF по шести внутрішніх межах
семи accepted-класів, на фактично accepted спробах, із перенормуванням
прогнозу на accepted. Нульова прогнозована accepted-маса позначається явно;
повний log loss залишається основним показником. Quantile повертає лише
інтервал, крайня нескінченна межа — null; точне середнє Δe не вигадується.

Порівняння log loss — paired spatial-cluster bootstrap, 1000 resamples,
seed42, percentile95%. За одного кластера інтервал не обчислюється, за
менш ніж 10 позначається exploratory. Число 10 — попереджувальна евристика,
не гарантія статистичної достатності. Окремі звіти: scene/condition/sigma.

Sensitivity: укрупнення до меж [-5,-1,1,5] та [-1,1] через точне складання
прогнозних мас. Порівнюють ранжування моделей усередині кожної постановки;
абсолютний log loss між різними розбиттями не порівнюють. Остаточний тест
не використовують для зміни порогів.

## Практична користь і критерій завершення

Можливості заздалегідь групуються за opportunity_group, condition, sigma,
trial. Одна спроба на групу; U=P(gain)−P(harm). Фактична utility: +1 для
gain, -1 для harm, 0 для reject/neutral. Великі шкоди додатково звітуються
в метрах та частотах; рівні ваги ±1 не є польотною функцією ризику.
Ties вирішуються за attempt_id без перегляду результату. Random control
оцінюється аналітично як середнє всіх доступних можливостей. Oracle regret
обмежено тим самим спостереженим набором, не іншими неіснуючими польотами.

На українських AOI без кадрів/еталона — тільки перевірка інтеграції.
Новий домен не отримує мовчки перевірений статус. Частота запитів задається
секундами, state propagation/camera config надходять від виклику.

Придатність потребує незалежних прогнозних переваг, оцінених погіршень та
практичної користі; один автоматичний score її не встановлює. За нестачі
сцен/подій результат непереконливий. validation_passed лишається false до
окремого обґрунтованого рішення. Похибка після fusion, безпечне прибуття,
реальна погода й target-platform калібрування не вважаються перевіреними.
