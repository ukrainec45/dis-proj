# Код для експерименту в Colab

Спільні модулі для трьох notebooks: основного експерименту, контрольної абляції
та швидкої перевірки видимості. Опис запусків і результати — у `docs/`.

Скопіюйте **цю папку цілком**, зі збереженням назви `visibility_localization`, у Google Drive. Приклад:

```text
MyDrive/
└── PhD/
    └── proj/scripts/
        └── visibility_localization/
            ├── __init__.py
            ├── core.py
            ├── data.py
            ├── backend.py
            ├── campaign.py
            ├── colab.py
            ├── analysis.py
            ├── check_upstream.py
            ├── test_experiment.py
            ├── requirements-colab.txt
            └── README.md
```

У розділі 2 notebook задайте **батьківський каталог** пакета:

```python
CODE_ROOT = Path('/content/drive/MyDrive/PhD/proj/scripts')
```

Notebook підключить Drive та імпортуватиме, наприклад:

```python
from visibility_localization.campaign import run_experiment
```

Він не записує код у Drive і не створює його копій у комірках. Після зміни модулів завантажте оновлені файли до тієї самої папки, перезапустіть Python-сеанс Colab та виконайте notebook зверху вниз. Це очищає попередні імпорти з пам'яті.

Основний notebook налаштований на `visibility-v7-aerial-roma-yaw-24`: aerial-карта/DSM,
CAMP + RoMa + P3P, 24 кадри (по шість із чотирьох сцен) × шість умов = 144 спроби.
Спочатку виконуються окремі 18 контрольних спроб на попередніх кадрах. Результати
зберігаються у Drive; для продовження перерваного запуску збережіть конфігурацію
та RUN_TAG. Завантажте
всю оновлену папку в Drive, перезапустіть Python-сеанс Colab і виконуйте notebook
зверху вниз. `map_alignment='prior_yaw'` повертає карту за шумною орієнтацією
профілю main (σyaw=5°); відповідності повертаються у вихідні координати перед DSM/PnP.
JSON/CSV показують фактичний matcher; для RoMa ідентичність містить стан
моделі й хеші двох checkpoint. Конфігурації без `matching_method` використовують SP_LG;
типове `map_alignment='none'` зберігає сумісність старих запусків.

`anyvisloc_visibility_quick.ipynb` використовує окремий авторський шлях з геометрією
та yaw із метаданих. Перший етап — 8 кадрів × 5 умов; `RUN_FULL=True` продовжує до
24 × 5. Ознаки карти кешуються для одного кадру; query, пошук і зіставлення
повторюються для кожної умови. Цей контроль не оцінює похибку реальної INS/VIO.

Завантаження RoMa/DINOv2 повторюється після тимчасових мережевих помилок;
`VISIBILITY_MODEL_CACHE` задає постійний кеш у Drive. Швидкий notebook перевіряє
повноту ConvNeXt у checkpoint CAMP і використовує його замість початкового
завантаження ImageNet-ваг; при продовженні звіряється хеш моделі.

Локальні перевірки:

```powershell
.venv/Scripts/python.exe -m pytest -q scripts/visibility_localization tests
```

CPU-тести використовують синтетичні відповідності та підміни нейромережевих
моделей. Вони не замінюють запуск CAMP/RoMa з реальними даними на GPU.

У версії `visibility-v3` пошук використовує висоту локального DSM біля prior.
За неможливої проєкції кадр переходить до пошуку ділянок 64/128/256 м навколо
зашумленого XY (`fallback_patch_sizes_m`). Масштаби є початковим інженерним
налаштуванням і не гарантують охоплення всіх висот. Великі ділянки карти
проходять retrieval зі зменшеною роздільністю; координати кандидатів та масштаб
повертаються до оригінальної карти для matching/PnP. Пороги прийняття пози не змінено.
Поля `geometry_fallback`, `retrieval_plane_source`, `retrieval_scales` пояснюють
використаний шлях. Завантажте всю оновлену папку в Drive та використайте новий RUN_TAG;
результати попереднього алгоритму не можна продовжувати під тією самою ідентичністю.

Код авторів AnyVisLoc клонується окремо в `/content/visibility_localization/Benchmark`. ZIP завантажуються в `/content/visibility_localization/archives`, розпаковуються в `/content/visibility_localization/data`. Код цієї папки читається з Drive. Місце результатів задається окремо через `SAVE_RESULTS_TO_DRIVE` і `RESULTS_ROOT`.

Сам AnyVisLoc не встановлюється через pip і не редагується. Python шукає авторський модуль у каталозі клонованого репозиторію:

```python
sys.path.insert(0, str(UPSTREAM_ROOT))
avl = importlib.import_module('avl_utils')
```

`importlib.import_module` виконує імпорт за назвою; для цього .py-файлу не потрібні метадані pip. Окремо адаптер `bind_upstream` створює функцію з тим самим скомпільованим тілом та копією словника глобальних імен. У копії підставляються фільтр пошуку за prior, кеш і спостереження за PnP. Це змінює залежності адаптованого виклику в пам'яті, але не переписує вихідні файли чи глобальні імена оригінальної функції. Адаптер залежить від внутрішніх імен авторського коду, тому commit зафіксовано.
